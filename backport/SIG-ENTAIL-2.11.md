BP-1 -- the signature-entailment check on Scala 2.11 (branch `backport-2.11`)
=============================================================================

Back-port of scala3-migration `5162945`'s SIG-3 work (`SigEntail.scala`, the
`Constraints.LabelSearch` lift, the three `Subst` call sites, the per-session mode, the
interface-key suffix, the oracle and the two test suites) to Scala 2.11.5 / sbt 0.13.5 /
JDK 8.  Measured 2026-09-12.  Brief: `backport/brief-BP-1.md`.  BP-2's library
corrections and pins (`backport/CORRECTIONS.md`) were in the tree for every gate below.

Result: the check ships at its `error` default.  The stdlib boots clean, `core/test` is
735/735, the engine agrees with the Python oracle on all 106 corpus signatures and with
exhaustive enumeration on 2,000 random systems, and `off` vs `error` over the whole
example corpus differs on exactly the five `sig0*` pins.


0.  Toolchain -- the commands that work
---------------------------------------
Written into the branch, so this need not be rediscovered:
`backport/env-2.11.sh` (JDK 8 + PATH + `SBT_OPTS` + the `sbt211` and `ermine211`
functions), `backport/repositories` (the resolver list), `backport/hg` (the shim).

    source backport/env-2.11.sh        # defines sbt211 and ermine211; idempotent

    sbt211 "export core/runtime:fullClasspath" | tail -1 > backport/.classpath

What `env-2.11.sh` does, and why each piece is needed:

    mercurial aborts in a git checkout.  The shim answers all three from git.
  * the genuine sbt 0.13.5 launcher jar, `~/.local/ermine-toolchain/bin/sbt-launch-0.13.5.jar`
    (from `https://repo.scala-sbt.org/scalasbt/ivy-releases/org.scala-sbt/sbt-launch/0.13.5/sbt-launch.jar`;

`5162945`'s 791-line Scala 3 file.  It needed NO `enum` / `given` / `extension` /
`then` / quiet-syntax work at all: the original is already written in a
2.11-compatible dialect (`sealed abstract class Mode` + `case object`s, explicit

changes, each marked `SCALA 2.11` in the file so the two versions diff cleanly:

    warning is now gone.  Nothing else renames.

7.  Literal column set on the left (2026-10-03)
-----------------------------------------------
Ported from the Scala 3 branch `sig-litlhs` (commit 2fc98615).  A partition
whose left-hand side is a written-out row, `(|K|) <- (p1..pk)`, used to be dropped by the
check, which then warned "NO VERDICT" and accepted.  A join against a projection produces
it, e.g. `join rows (project {key} rows)`.  The check now encodes it with a variable of its
own, `z <- (|K|)` and `z <- (p1..pk)`, the same thing `Constraints.PQueue.build` does for
the solver.  The variable is chosen when the constraint is an obligation and rigid when it
is a given.
