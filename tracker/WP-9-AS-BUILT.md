`npm run bundle` is `npm run build && webpack`. **`bundle:watch` was a trap and is fixed
(M-3).** As first written it was a bare `webpack --watch`, which the review MEASURED doing
two wrong things: editing `src/host/index.ts` rebuilt **nothing** (webpack watches
`dist/src/`, the tsc output — the cost of Q-B), and from a clean checkout it failed
outright with `Module not found: Can't resolve './dist/src/index.js'`, because it never ran
`build`. Documenting "run `tsc --watch` beside it" was not enough: a watch that silently
ignores the files you are editing is worse than no watch.

**The choice made, and why.** `bundle:watch` now runs `client/scripts/bundle-watch.js`:
one full `tsc` (a type error aborts there rather than leaving a half-watched tree), then
`tsc --watch --preserveWatchOutput` and `webpack --watch` as two children with inherited
stdio, SIGINT/SIGTERM/SIGHUP forwarded to both, and either child's exit stopping the other.
The alternatives were a `concurrently`-style dependency (rejected: one more package to
vendor forever, which is the whole point of Q-B) and two documented scripts (rejected: that
is what was there, and it is what failed). **Both children are spawned as
`node <their own cli entry>`** rather than through `node_modules/.bin`, so there is no
`.cmd` shim question on Windows — which §10 says the deployment machines are. Still no dev
server, per §5.

MEASURED after the change, on a tree with `dist/` deleted: the first bundle builds
(`ermine-host.js` sha `4ee1cbc7…`), then appending a line to `src/host/index.ts` changed
the bundle's sha within the probe window, and Ctrl-C (SIGINT) left **no** stray `tsc` or
`webpack` process (`ps -eo args | grep -E "bundle-watch|--watch"` empty afterwards).

## 6. The host reducer, and why it decides nothing

`client/src/host/index.ts` follows the design review's **D10** to the letter: there are two
reducers over overlapping state — WP-7's `stuckReduce` in `editor/vscode/src/preview-core.js`
and this one — and they cannot disagree because **only one of them decides anything**.

* Every DECISION stays **EXTENSION-SIDE**: is this answer current, is this `seq` newer,
  should we re-render, did the wedge clear, is the pick held. Extension-side is two files,
  and the split is the extension's own (`editor/vscode/src/extension.js:277-285`, READ,
  which explicitly retracts the wording "EVERY DECISION IS IN `src/preview-core.js`"):
  what is decidable **from data alone** lives in `preview-core.js` and is unit-tested
  there; what needs **the editor itself** stays in `extension.js`. D10's substance is
  unchanged — what matters is that the decisions are not HERE.
* `applyMessage` decides only what the panel SHOWS for a message it is handed.

Two visible consequences, both deliberate and both pinned by a test:

* **No `seq` arbitration here.** §4's client-contract rule (1) — keep the highest `seq`,
  reset the mark on Stopped → Running — is the extension's. `(h-stuck-no-arbitration)`
  pins that a lower `seq` is applied as sent. **If the reviewer thinks the panel should
  arbitrate instead, this is the line to argue with**; §5's Stuck row says "the panel
  keeps the highest it has seen", which D10 overrides, and I followed D10.
* **A `render` does not clear `stuck` or `held`.** Rule (2) makes the notification
  authoritative for the wedge and WP-22's mark is the extension's.

Nine message kinds: §5's `render`, `error`, `stale`, `stuck`, `reloadBundle`, `unsaved`,
`switching`, `offline`, plus WP-22's `held`. §4's rule (5) is **withdrawn** (WP-24), so
nothing here treats a missing falling edge as special.

Banner precedence, highest first: `offline > stuck > held > reloading > switching > error >
stale > initial`. The first three are WP-22's own status-bar order; the three in the middle
are states the status bar has no branch for, placed above `stale` (WP-22's "rendering").
The `initial` banner is §5's "Pick a report: **Ermine: Preview Report...**", which also
answers the gap the design review's §4.4 found — a panel with no document always says
something. `unsaved` is a HINT beside the banner, never instead of it (§5).
`held` carries **no** panel button: WP-22 puts **Render anyway** in an extension-side
`showWarningMessage`, so duplicating it in the panel would be a second decision site.

The reducer is total: a message kind it does not know returns the state **by identity**
(`(h-unknown)`), so a newer extension cannot blank an older panel.

**`reloading` gained a falling edge (S-1).** It was the only latch without one, and it
outranks `error`: the review MEASURED it winning **16.5 %** of all generated states once
raised. A real reload destroys this page (§5 re-sets `webview.html`), so the flag can only
ever survive a reload that did NOT happen — debounced away, or a failed write — and in that
case it would have masked every later failure for the life of the panel. **The rule chosen:
any ANSWER clears it**, `render` and `error` alike, because an answer arriving proves this
page is still alive and talking. Clearing on `render` alone would not have met the reason
the coordinator gave for the fix ("must not mask errors for ever"), since `reloading`
outranks `error` in the precedence; the alternative, demoting `reloading` below `error`,
would have been two changes rather than one and would have left the latch permanent.
`(h-reload-cleared)` pins both edges and that **nothing else** clears it.

**The dimming rule is now one sentence (S-2)**, in `Presentation.dimmed`'s doc comment: a
document on screen is dimmed exactly when **nothing is currently trying to replace it**.
That is why `offline`, `error`, `switching` and `held` dim (the panel has stopped trying)
and `stale`, `stuck` and `reloading` do not (`stale` and `stuck` are still in flight —
Q10's recovery can still bring a wedged job back — and `reloading` is about to be replaced
wholesale, where a flicker would buy nothing). `(h-dim-table)` pins all seven rows plus
"nothing is dimmed when nothing is on screen".

**The properties found one real defect.** `(h-prop-consistent)` falsified on
`{kind: "stuck", stuck: true, message: ""}`: §4 promises no non-empty `message`, and taking
it literally drew a banner that said nothing at all — a coloured strip with no text, which
is worse than no banner. Fixed by normalising blank strings to "missing" at the reducer's
boundary (`nonBlank`), which also removed "switching to " and "500: " from the possible
outputs. `(h-blank)` pins it. This is the value D9 predicted from making a checklist row a
test, arriving one ticket early.

The host module imports **nothing** — not `../document`, not zod — so `ermine-host.js` is
9,992 B and the two bundles share no dependency. The document is carried as an opaque
payload and handed to `ErmineClient.parseDocument` by the panel.
