# tracker/db

The DB programme's local SQL Server is SQL Server 2022 Developer. It runs in a rootless podman container called `ermine-mssql` and listens on `127.0.0.1:1433` only. Start it with `scripts/db.sh up`: this creates the container if it is missing, starts it, waits until every database is online, and creates or refreshes the `ermine` login and the databases `ErmineSales`, `ErmineHR` and `ErmineScience`. `scripts/db.sh status` prints one line per fact: container state and health, which databases exist, whether the login works, and memory. `scripts/db.sh down` stops the server and keeps the data. `scripts/db.sh down --all` removes the container and the data volume `ermine-mssql-data`, but keeps the image and the `/load` directory. Nothing starts on its own: the restart policy is `no`, so run `up` after a reboot. `scripts/db.sh sql DB "QUERY"` and `scripts/db.sh sql DB -i FILE` run SQL as `ermine`, and `--sa` runs it as `sa`. The recipe, measurements and known gaps are in [CONTAINER.md](CONTAINER.md).

The passwords are stored in only one place: `~/.config/ermine/db.env`, outside the repo, mode 600, directory mode 700. It holds `MSSQL_SA_PASSWORD` and `ERMINE_DB_PASSWORD`. `db.sh` reads that file on every call. It passes the passwords to sqlcmd through the `SQLCMDPASSWORD` environment variable and to the container through `--env-file`, so they never appear on a command line, in the repo, in the board or in a log. To rotate the `ermine` password, edit the file and run `scripts/db.sh up`, which re-applies it with `ALTER LOGIN`. The SA password only takes effect when the volume is first created (see CONTAINER.md, known gaps). Passwords must match `[A-Za-z0-9_.-]{8,128}`, because `db.sh` substitutes them into T-SQL string literals. Exit codes are listed in `scripts/db.sh --help`; exit 3 includes "sa login refused". The VS Code extension asks for the `ermine` password once per window (WP-13) and does not read this file.
