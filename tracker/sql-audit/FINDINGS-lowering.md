## L-2 Flat emission of nested UNION/EXCEPT (SQL Server)

`DistinctiveQuery.union` (`:1087-1092`) builds `SqlUnion(asOrderable(q1), asOrderable(q2))`; a `SqlNaryOp` is `Orderable`, so
an `EXCEPT` node is passed straight in; `SqlUnion.apply` flattens only same-op children, so the tree is `SqlNaryOp(Union, [A, SqlNaryOp(Except, [B, C])])`
and the default `emitNaryOp` (`SqlEmitter.scala:237`) prints `A UNION B EXCEPT C`. T-SQL evaluates UNION and EXCEPT left to right (INTERSECT binds tighter).
Live SQL Server (`scripts/db.sh sql ErmineSales`), literals r1, r2, r3 as above:

| relation | emitted | live rows | expected |
|---|---|---|---|
| `union r1 (difference r2 r3)` | `A UNION B EXCEPT C` | (1,a,1) (1,b,2) (3,z,9) | + (2,c,3) |
| `difference r1 (union r2 r3)` | `A EXCEPT B UNION C` | (1,a,1) (2,c,3) (2,e,5) | (1,a,1) only |
| `difference r1 (difference r2 r3)` | `A EXCEPT B EXCEPT C` | (1,a,1) | (1,a,1) (2,c,3) |

SQLite is correct because `SqliteEmitter.emitNaryOp` wraps every operand in `select * from (...)`. Fix in the scanner: in `union`, `selectWrap`
the right operand when it is a `SqlNaryOp` whose op is not `SqlUnion`; in `minus`, wrap a right operand that is any `SqlNaryOp`. Left-nested
trees (`union (difference a b) c`, `difference (union a b) c`) are already correct under left-to-right evaluation. `lookupLatest'` (`Relation.e:256-260`) nests `union` over `difference` and is affected on SQL Server.

## L-3 squashLiteral ignores windows

`joinOn` (`:1125-1131`) squashes a single-row literal side into the other side's select (`squashLiteral`, `:1104-1116`), adding `SqlEq(v.attrs(r), lit)`
to `where` (or `having` when aggregated). Unlike the general path (`:1133-1146`) it has no `!v.isWindowed` guard. Live SQL Server:

- `join (relation [{x = 1}]) wrank` -> `select ..., (RANK() over (partition by k order by x desc)) [y] from (...) t where (t.x = 1)` -> `y = 1`; the rank of x=1 among k=1's {1,2} by x desc is 2.
- `join (relation [{y = 1}]) wrank` -> `where ((RANK() over (...)) = (1))` -> `Msg 4108: Windowed functions can only appear in the SELECT or ORDER BY clauses`.

Fix: `val v = asSelect(h, q, v => !v.isWindowed)` in `squashLiteral` (the predicate then lands in the wrapping select's WHERE, as `q_sq_lim_M.sql` shows for the limited case, which is already handled correctly by the wrap).

## L-6 Aggregate over an empty input

## L-7 LimitM is 0-based where everything else is 1-based
