## Behaviour a report author would notice (one sentence each)

- Window helpers (`rankWithin`, running and moving sums), `dateAdd`, `dateDiff`, `tryCast`, `standardDeviationBy`/`varianceBy`, a field named `group`/`order`/`select`/`user`, `join a (join b c)` and `limit o (Just n) Nothing` now run on the default (SQLite) runner instead of failing with a syntax error or a "todo" exception.
- On SQLite `x // y` over doubles now floors (7.5 // 2.0 = 3.0, as in memory and on SQL Server), `show n`/`a ++ b` over a NULL gives the other text instead of dropping the row with "Unexpected NULL", a timestamp literal compares correctly against a timestamp column, `cast d String` gives `2024-01-15` rather than the milliseconds, and an average of an Int column is a whole number as on SQL Server.
- On SQL Server, string literals with characters outside the database code page (CJK, emoji, Cyrillic) arrive intact, date literals no longer depend on the login's language, every `letR`/`materialize`/large-literal temp table is dropped after its scan, `1.0 / 3.0` is a float division, and aggregates over an empty relation, an all-NULL column, or a grouped query whose key was folded to a constant no longer error or return a phantom row.
- A `limit` ordered by two columns that share an expression, or by a constant column, no longer errors on SQL Server.
- `NaN`/`Infinity` doubles in a relation literal become NULL on every dialect instead of invalid SQL.
- A nested `if` in the consequent branch now answers the outer `else` when the test is unknown (NULL), as the in-memory evaluator does.
- SQL Server unbounded strings are `nvarchar(max)` (casts no longer truncate at 1000 characters); a let-bound relation with a string primary/index key stores that key column as `nvarchar(450)` (was 1000).

## Departures from the worklist, open issues, questions for other areas

- E12 departure: the worklist says `nvarchar(max)`; a `CREATE TABLE` key/index/FK column gets `nvarchar(450)` instead, because SQL Server refuses to index a `max` column (`letRWithPK {sensorId,..}` and `memoRelWithPK` with a string key would have failed hard).  Non-key columns and every CAST are `max`.
- E1/E19 for MySQL: the base `emitOver` now raises for MySQL (5.x has no window functions) where it used to splice TODO text; Vertica and PostgreSQL got `EmitOver_UsingOver` text-level, untested live.  E22 on MySQL stays an untyped NULL (MySQL's CAST names differ).  E17 on MySQL not done: `CONCAT` returns NULL for a NULL operand there too (would need `COALESCE`), untested, noted only.
- E9 rule choice: SQLite `cast d String` gives ISO `2024-01-15` (SQL Server's text), NOT the in-memory `PrimExprs.dateFormatter` locale format (`1/15/24`); a string that is not a date casts to NULL rather than raising.  The in-memory `cast "2024-01-15" Date` itself fails (`dateFormatter` is the locale SHORT format, `timestampFormatter` wants a zone): prims area, seen while writing the E9 property (its rows are made non-constant so the optimizer does not fold the cast in memory).
- Found and fixed outside the list: integral AVG on SQLite (above).  impl-prims P4: the in-memory average of Ints should truncate toward zero to agree with SQL Server and this fix.
- impl-prims P7: my SQLite `dateAdd` is verified against a GMT `Calendar#add`; `TimeUnit.incrementTimestamp` uses the JVM default zone today, so in-memory and SQL disagree across DST until P7 lands.
- impl-scanner C6 (D2): `emitEmpty`/`SqlNullOf` type the NULLs; the `coalesce(sum,0)` / `having count(*) > 0` for an ungrouped aggregate over no rows is still the scanner's.  The differential's `emptyAgg` class passed with my changes alone (1000 random), so the oracle's reference must already accept one NULL row there; C6 changes that and the flag should be re-checked when both land.
